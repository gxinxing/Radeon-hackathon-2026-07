## Decision: Make `track3-soccer/` the single source of truth for Track 3 code, orchestration records, and sanitized operations material
## Context: Track 3 files were spread across the project, WorkBuddy's `track3_graph_engine`, a sibling `radeon_ssh` directory, the Radeon GPU workspace, and GitHub. With two days remaining, this created stale handoffs and conflicting claims about which implementation was current.
## Alternatives considered: Keep each agent's files in its own workspace; make the remote GPU workspace authoritative; make GitHub the only working location; consolidate durable material under `track3-soccer/` while keeping secrets and runtime-heavy state external/ignored.
## Reasoning: A local canonical tree supports fast integration and review, while Git provides durable history and the Radeon instance remains an execution mirror. Preserving legacy WorkBuddy material inside the canonical tree retains context without treating its placeholder verifiers as authoritative. Separating tracked orchestration records from ignored runtime logs avoids repository noise and credential leakage.
## Trade-offs accepted: Existing absolute WorkBuddy paths remain temporarily duplicated for compatibility; runtime logs and large artifacts will not be byte-identical across GitHub; synchronization requires explicit hash/status reconciliation; SSH keys remain outside the canonical project even though this means not every operational byte is physically stored under it.
